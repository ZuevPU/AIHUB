# Конструктор для учителя: урок / задание / рабочий лист

Спецификация нового раздела AIhub. Один конструктор, три сущности, общий профиль.
Документ описывает методическую логику, эталонные промпты, модель данных и UX.
Тексты промптов и списки вариантов — содержательная часть, менять их нельзя.

---

## 1. Зачем это устроено именно так

Учитель редко проектирует урок, задание и рабочий лист по отдельности. Это одна
работа: тема одна, класс один, планируемый результат один. Разводить их по трём
страницам — заставлять человека три раза вводить одно и то же.

Отсюда три решения:

**Общий профиль.** Предмет, класс, тема, оснащение, особенности класса заполняются
один раз в шапке и подставляются во все три сущности. Переключение сущности не
сбрасывает профиль.

**Перенос контекста.** Собрал урок — кнопкой «Сделать задание по этому уроку»
переходишь на вторую сущность с сохранённым профилем и темой. Это основной сценарий
использования, а не дополнительная функция.

**Обязательная проверка согласованности.** Каждый из трёх промптов заканчивается
требованием к модели: сопоставить заявленный результат, деятельность и способ
проверки, и честно сказать, где связь не выстроена. Без этого блока генератор
выдаёт правдоподобные, но методически рассыпающиеся материалы — заявлено «умеет
анализировать», а проверяется воспроизведение определения.

Ещё одно требование ко всем трём: блок «мои допущения» в конце. Модель обязана
перечислить, что она домыслила за учителя. Это превращает результат из готового
документа в черновик с обозначенными швами — что честнее и безопаснее.

## 2. Общий профиль (шапка страницы)

Одна панель, липкая при прокрутке. Поля общие для всех трёх сущностей.

| Поле | id | Тип | Варианты / значение по умолчанию |
|---|---|---|---|
| Предмет | `subject` | text | «информатика» |
| Класс | `grade` | select | 5, 6, 7, 8, 9, 10, 11 классы, СПО 1 курс, СПО 2 курс |
| Тема | `topic` | text | «алгоритмы и исполнители» |
| Место темы в разделе | `topicPlace` | select | первый урок по теме / середина раздела / завершение раздела / повторение перед контрольной |
| Оснащение | `equipment` | select | компьютерный класс, у каждого ПК / один ПК и проектор у учителя / ноутбуки на группу / смартфоны учеников / без техники, только тетради |
| Особенности класса | `classProfile` | select | базовый уровень / углублённый уровень / сильный разрыв в подготовке / много неуспевающих / есть ученики с ОВЗ, нужна адаптация |
| Роль ИИ в материале | `aiRole` | select | ИИ только у меня как у учителя / ученики используют ИИ как инструмент / ИИ — объект изучения на этом уроке / ИИ не используется учениками |

`aiRole` не декоративное поле. Оно меняет содержание генерации: при «ученики
используют ИИ» в материал добавляется блок правил работы с нейросетью и проверки
её ответов, при «ИИ — объект изучения» тема разворачивается на разбор того, как
модель ошибается.

## 3. Сущность «Урок»

### 3.1 Секции конструктора

**Тип урока** (`lessonType`, select, обязательное)
- открытие нового знания
- отработка и применение
- систематизация и обобщение
- развивающий контроль
- проектная или исследовательская работа
- урок-практикум за компьютером

**Продолжительность** (`duration`, select) — 40 минут / 45 минут / спаренный, 2×45 / 30 минут, сокращённый

**Методический каркас** (`framework`, select)
- системно-деятельностный подход
- проблемное обучение
- перевёрнутый класс
- исследовательский цикл: гипотеза, проверка, вывод
- станционная работа
- обучение через ошибку: разбор неверного решения

**Мотивационный вход** (`hook`, select)
- проблемная ситуация, в которой известный способ не работает
- парадокс или контринтуитивный факт
- задача из жизни учеников
- демонстрация результата, который хочется повторить
- ошибка в готовом решении, которую надо найти

**Доля деятельности учеников** (`activityShare`, select) — не менее половины урока / не менее двух третей урока / урок целиком практический

**Формирующее оценивание** (`formative`, select)
- светофор или сигнальные карточки на ключевых точках
- билет на выход: два вопроса в конце
- взаимопроверка в парах по критериям
- короткий устный опрос по цепочке
- наблюдение за работой групп по чек-листу

**Дифференциация** (`differentiation`, select)
- по сложности: три уровня одного задания
- по темпу: обязательная часть плюс задания для тех, кто закончил
- по степени поддержки: карточки-подсказки для тех, кому трудно
- по способу работы: индивидуально или в паре на выбор
- без дифференциации, класс ровный

**Рефлексия** (`reflection`, select)
- возврат к вопросу, поставленному в начале урока
- «что я теперь умею» по планируемым результатам
- незаконченное предложение по содержанию темы
- шкала уверенности с обоснованием
- без отдельного этапа, рефлексия встроена в задания

**Домашнее задание** (`homework`, select)
- обязательная часть и задание по выбору
- подготовка к следующему уроку, опережающее
- творческое или проектное задание
- отработка того, что не получилось на уроке
- без домашнего задания

**Формат вывода** (`output`, select)
- технологическая карта в виде таблицы по этапам
- развёрнутый сценарий с репликами учителя
- краткий поэтапный план с хронометражем
- каркас урока: только этапы, цели и время, наполню сам

### 3.2 Эталонный промпт

```
Ты — методист и педагогический дизайнер с опытом проектирования уроков по предмету
«{{subject}}». Ты работаешь по ФГОС, отличаешь деятельность ученика от рассказа
учителя и не путаешь планируемый результат с содержанием темы.

КОНТЕКСТ
Предмет: {{subject}}
Класс: {{grade}}
Тема урока: {{topic}}
Место темы в разделе: {{topicPlace}}
Тип урока: {{lessonType}}
Продолжительность: {{duration}}
Оснащение: {{equipment}}
Особенности класса: {{classProfile}}
Роль ИИ: {{aiRole}}

ЗАДАЧА
Спроектируй урок и оформи его как: {{output}}.
Методический каркас: {{framework}}.

ТРЕБОВАНИЯ К ПРОЕКТИРОВАНИЮ

1. Начни с планируемых результатов, а не с содержания.
   — Предметные: 2–3, каждый через наблюдаемое действие ученика («строит алгоритм»,
     «сравнивает два способа», «находит ошибку в коде»). Формулировки «знает»,
     «понимает», «имеет представление» не принимаются: их нельзя проверить.
   — Метапредметные: 2–3, с прямым указанием, на каком этапе урока они реально
     формируются. Если этап назвать не можешь — не заявляй результат.
   — Личностные: не более одного, и только если тема даёт для этого настоящий повод.
     Если повода нет — так и напиши, не притягивай.

2. Каждому этапу урока сопоставь четыре колонки: время, что делает учитель, что
   делает ученик, какой планируемый результат отрабатывается.
   Деятельность учеников занимает {{activityShare}}.

3. Мотивационный вход: {{hook}}. Опиши его конкретно — назови вопрос, ситуацию,
   объект, число. Формулировка «учитель создаёт проблемную ситуацию» бесполезна:
   учителю нужно то, что он произнесёт вслух.

4. Встрой формирующее оценивание: {{formative}}. Это точка, где учитель до конца
   урока понимает, кто не освоил материал. Укажи, что учитель делает, если
   выясняется, что не поняла половина класса.

5. Дифференциация: {{differentiation}}. Опиши конкретно, что делает ученик, которому
   легко, и ученик, которому трудно, — не общий принцип, а задание.

6. Рефлексия: {{reflection}}. Привяжи её к цели урока, а не к настроению.

7. Домашнее задание: {{homework}}. Укажи ожидаемое время выполнения.

ОГРАНИЧЕНИЯ
— Не используй обороты «дать понятие», «познакомить учащихся», «закрепить материал»,
  «формировать умение»: это описание работы учителя, а не результат ученика.
— Не предлагай активности, невозможные при оснащении «{{equipment}}».
— Не выдумывай номера параграфов, задач и страниц учебника, названия УМК и цитаты
  из нормативных документов. Где нужна опора на учебник, ставь метку [указать: §].
— Хронометраж этапов в сумме должен давать {{duration}}. Проверь арифметику.
— Не пиши вводных абзацев о важности темы. Сразу материал.

ФОРМАТ ОТВЕТА
{{output}}

ЗАВЕРШАЮЩИЕ БЛОКИ — обязательны, оформи отдельно после основного материала.

А. Проверка согласованности.
   Таблица: планируемый результат → этап, где формируется → чем проверяется на этом
   уроке. Если какой-то результат нигде не проверяется — напиши это прямо, не
   подгоняй таблицу под красивый вид.

Б. Что может пойти не так.
   Три конкретных риска этого урока (по времени, по пониманию, по организации) и
   что делать учителю в каждом случае.

В. Мои допущения.
   Что ты домыслил за меня: об уровне класса, о предыдущих темах, о доступных
   средствах. Что я должен проверить перед проведением урока.
```

## 4. Сущность «Задание»

### 4.1 Секции конструктора

**Когнитивный уровень** (`cognitiveLevel`, select) — по таксономии Блума, формулировки развёрнуты, чтобы учитель не гадал:
- воспроизведение: назвать, определить, перечислить
- понимание: объяснить своими словами, привести пример
- применение: решить по известному способу в новой ситуации
- анализ: разобрать на части, найти причину, сравнить
- оценка: обосновать выбор, найти ошибку в чужом решении
- создание: спроектировать, собрать собственное решение

**Формат задания** (`taskFormat`, select)
- задача с однозначным ответом
- открытый вопрос с развёрнутым ответом
- найди и исправь ошибку в готовом решении
- восстанови пропущенное: код, схему, шаг алгоритма
- сопоставление: соотнести два ряда
- учебный кейс с несколькими вопросами
- мини-исследование с выводом
- практическое задание за компьютером

**Контекст задания** (`taskContext`, select)
- учебный, внутри предмета
- бытовой, из жизни учеников этого возраста
- межпредметный: связь с другим школьным предметом
- профессиональный: как эта задача выглядит в работе
- игровой или соревновательный

**Количество** (`taskCount`, select) — 3 задания / 5 заданий / 8 заданий / 12 заданий на карточку

**Вариативность** (`variability`, select)
- один вариант
- два равноценных варианта для контрольной работы
- три уровня сложности одного задания
- индивидуализированные: разные данные, одна структура

**Что приложить** (`taskExtras`, select)
- ответы
- ответы и решения
- ответы, решения, критерии оценивания в баллах
- ответы, решения, критерии, типичные ошибки с разбором

### 4.2 Эталонный промпт

```
Ты — методист по предмету «{{subject}}» и специалист по разработке учебных заданий.
Ты умеешь отличать задание, которое проверяет заявленное умение, от задания, которое
выглядит сложным, но решается подстановкой.

КОНТЕКСТ
Предмет: {{subject}}
Класс: {{grade}}
Тема: {{topic}}
Место темы в разделе: {{topicPlace}}
Особенности класса: {{classProfile}}
Оснащение: {{equipment}}
Роль ИИ: {{aiRole}}

ЗАДАЧА
Разработай {{taskCount}} по теме «{{topic}}».
Формат: {{taskFormat}}.
Контекст: {{taskContext}}.
Когнитивный уровень: {{cognitiveLevel}}.
Вариативность: {{variability}}.

ТРЕБОВАНИЯ

1. Соответствие уровню. Задание уровня «анализ» не может выполняться подстановкой
   в формулу, а задание уровня «создание» — выбором из вариантов. Если для темы
   заявленный уровень недостижим — скажи об этом прямо и предложи ближайший
   достижимый, объяснив почему.

2. Самодостаточность условия. Ученик не должен догадываться, что имелось в виду.
   Все данные, единицы измерения и ограничения — в условии.

3. Проверяемость. Для каждого задания должно быть ясно, что считается верным
   выполнением. Формулировки вроде «раскройте тему» не принимаются.

4. Правдоподобие данных. Числа должны сходиться, ситуации — быть возможными.
   Если контекст «{{taskContext}}» для этой темы натянут, не изобретай искусственную
   связь с жизнью: лучше честное учебное задание, чем фальшивое прикладное.

5. Калибровка по классу «{{grade}}»: словарь, объём условия и вычислительная
   сложность соответствуют возрасту. Длинное условие — отдельная сложность,
   не всегда нужная.

6. К каждому заданию приложи: {{taskExtras}}.
   Типичные ошибки описывай диагностически: не просто «ошибётся в порядке действий»,
   а что именно это говорит о пробеле ученика.

ОГРАНИЧЕНИЯ
— Никаких заданий на угадывание того, что имел в виду автор.
— Не используй задания, требующие оборудования, которого нет: {{equipment}}.
— Не выдумывай статистику, исторические факты, цитаты и номера задач из учебника.
  Сомнительное помечай меткой [проверить].
— Не оценивай личность ученика в формулировках заданий и критериев.

ФОРМАТ ОТВЕТА
Каждое задание отдельным блоком: номер, формулировка для ученика, затем служебная
часть для учителя. Служебную часть визуально отдели, чтобы её можно было не печатать.

ЗАВЕРШАЮЩИЕ БЛОКИ — обязательны.

А. Проверка соответствия.
   Таблица: номер задания → заявленный когнитивный уровень → чем подтверждается,
   что задание действительно этого уровня. Где не сходится — признай.

Б. Чем это оценивать.
   Если критерии заказаны — сведи их в одну шкалу. Если нет — одной строкой скажи,
   на что смотреть при проверке.

В. Мои допущения.
   Что ты домыслил о пройденном материале и уровне класса. Что проверить перед выдачей.
```

## 5. Сущность «Рабочий лист»

### 5.1 Секции конструктора

**Режим работы** (`worksheetMode`, select)
- индивидуально на уроке
- в паре на уроке
- в группе на уроке
- дома, самостоятельно
- на замене, без учителя-предметника
- для ученика, пропустившего тему

**Самостоятельность** (`autonomy`, select)
- ученик проходит лист полностью сам, без объяснений учителя
- лист сопровождает объяснение учителя
- лист для отработки после объяснения

**Объём** (`volume`, select) — одна страница А4 / две страницы А4 / разворот, две страницы с разными блоками

**Опоры** (`supports`, select)
- образец выполнения первого задания
- краткий справочник терминов на полях
- пошаговая инструкция-алгоритм
- подсказки, к которым можно обратиться при затруднении
- без опор, лист диагностический

**Последовательность заданий** (`progression`, select)
- от простого к сложному, равномерно
- точка входа для всех, затем резкий рост сложности
- по этапам одного процесса
- от разбора образца к самостоятельному выполнению

**Самопроверка** (`selfCheck`, select)
- ответы для сверки в конце листа
- критерии, по которым ученик проверяет себя сам
- контрольный вопрос после каждого блока
- без самопроверки, лист сдаётся учителю

**Формат вывода** (`worksheetOutput`, select)
- markdown для печати, с разметкой полей для ответов
- таблица, готовая к вставке в документ
- HTML для печати на A4
- текст с явной разметкой «здесь пишет ученик»

### 5.2 Эталонный промпт

```
Ты — педагогический дизайнер. Ты разрабатываешь рабочие листы, с которыми ученик
{{grade}} работает {{worksheetMode}}. Ты пишешь для ученика, а не для проверяющего:
на листе не должно быть ни одного слова из методической документации.

КОНТЕКСТ
Предмет: {{subject}}
Класс: {{grade}}
Тема: {{topic}}
Место темы в разделе: {{topicPlace}}
Особенности класса: {{classProfile}}
Оснащение: {{equipment}}
Роль ИИ: {{aiRole}}
Степень самостоятельности: {{autonomy}}

ЗАДАЧА
Разработай рабочий лист объёмом {{volume}}.

ОБЯЗАТЕЛЬНАЯ СТРУКТУРА ЛИСТА

1. Шапка: фамилия, класс, дата.
2. Цель на языке ученика: «К концу листа я смогу…», одна-две строки. Без слов
   «планируемые результаты», «УУД», «компетенции» — ученик их не читает.
3. Инструкция: что делать, сколько это займёт, чем можно пользоваться, что делать
   при затруднении. Каждая инструкция — одно действие.
4. Опоры: {{supports}}. Размести их так, чтобы они не подсказывали ответ раньше времени.
5. Задания, выстроенные так: {{progression}}. Первое задание должен выполнить каждый
   ученик класса — это точка входа, а не фильтр.
6. Место для ответа, соразмерное ожидаемому объёму: строка для слова, поле для схемы,
   таблица для расчёта. Явно обозначь, где ученик пишет.
7. Самопроверка: {{selfCheck}}.
8. Чек-лист «я умею»: 3–4 пункта, сформулированные как действия, ученик отмечает себя.
9. Рефлексия: одно короткое действие, а не сочинение.

ТРЕБОВАНИЯ К ТЕКСТУ
— Обращение на «ты», короткие предложения, глаголы в повелительном наклонении.
— Термин при первом появлении объясняется тут же, в скобках или на полях.
— Никакого канцелярита и никаких предложений длиннее двух строк.
— Объём должен реально помещаться в {{volume}}. Не набивай лист сверх меры: пустое
   место для записи — часть конструкции, а не расточительство.

ОГРАНИЧЕНИЯ
— Не давай заданий, требующих оборудования, которого нет: {{equipment}}.
— Не выдумывай факты, числа и цитаты. Сомнительное помечай [проверить].
— Не используй формулировки, оценивающие ученика: «это легко», «как вы уже знаете»,
   «внимательный ученик заметит».

ФОРМАТ ВЫВОДА
{{worksheetOutput}}

ОТДЕЛЬНО ПОСЛЕ ЛИСТА — обязательные блоки для учителя, визуально отделённые.

А. Ключ.
   Ответы, критерии, время на каждое задание, общее время прохождения листа.

Б. Где застрянут.
   Два-три места, в которых ученики споткнутся, и что учителю сказать или показать.
   Если лист рассчитан на работу без учителя — что должно быть на листе, чтобы
   ученик прошёл это место сам.

В. Мои допущения.
   Что ты домыслил о предыдущих темах и уровне класса. Что проверить перед печатью.
```

## 6. Модель данных

```ts
export type TeacherEntity = 'lesson' | 'task' | 'worksheet'

export interface BuilderField {
  id: string
  label: string
  type: 'select' | 'text'
  options?: string[]
  defaultValue: string
  placeholder?: string
  /** Короткое пояснение под полем: зачем этот выбор влияет на результат. */
  hint?: string
}

export interface BuilderSection {
  id: string
  title: string
  /** Одна строка: что этот блок меняет в итоговом материале. */
  caption?: string
  fields: BuilderField[]
}

export interface EntityConfig {
  entity: TeacherEntity
  label: string
  /** Что получит учитель на выходе — показывается под переключателем. */
  outcome: string
  sections: BuilderSection[]
  /** Шаблон промпта с плейсхолдерами {{field_id}}. */
  template: string
}

export interface TeacherProfile {
  subject: string
  grade: string
  topic: string
  topicPlace: string
  equipment: string
  classProfile: string
  aiRole: string
}
```

Сборка промпта — чистая функция без побочных эффектов:

```ts
export function buildTeacherPrompt(
  config: EntityConfig,
  profile: TeacherProfile,
  values: Record<string, string>,
): string
```

Порядок разрешения плейсхолдера: поле профиля → значение секции → значение по
умолчанию. Пустая строка допустима и не должна оставлять висящих пустых абзацев:
после подстановки схлопнуть три и более переводов строки до двух.

## 7. UX

**Структура страницы сверху вниз:** заголовок → переключатель сущности → профиль
учителя → секции выбранной сущности → превью промпта.

**Переключатель сущности** — сегментированный контрол из трёх кнопок с подписями
«Урок», «Задание», «Рабочий лист». Под ним одна строка `outcome`: что учитель
получит на выходе. Переключение не сбрасывает ни профиль, ни значения других
сущностей — учитель может собрать урок, переключиться на задание и вернуться.

**Превью промпта** — липкая панель справа на широких экранах, сворачиваемый блок
внизу на узких. Действия: копировать, сбросить сущность, скачать в `.md`.
Randomize не нужен: у учителя нет задачи получить случайный урок.

**Перенос контекста.** Под превью — две кнопки: «Сделать задание по этому уроку» и
«Сделать рабочий лист». Переключают сущность, сохраняя профиль. Для сущности
«Урок» показываются обе, для остальных — две оставшиеся.

**Отзывчивость.** На узких экранах секции идут в одну колонку, превью сворачивается
в блок с кнопкой «Показать промпт». Все интерактивные элементы доступны с клавиатуры,
фокус видим.

## 8. Встраивание в AIhub

- Маршрут: `/teacher/material-builder`, ленивая загрузка, как у остальных конструкторов.
- Ось «Для кого»: `audience: ['obrazovanie']`. Если тип `MaterialAudience` ещё не
  добавлен, вводится по образцу госслужбы, поле необязательное, старые материалы

- Режим встраивания работает через существующий `useIsEmbedded` без правок.
- Никаких новых зависимостей: React, react-router, lucide-react, Tailwind.

## 9. Чек-лист приёмки

1. `/teacher/material-builder` открывается, по умолчанию активна сущность «Урок».
2. Переключение между тремя сущностями не сбрасывает профиль учителя.
3. Значения, выбранные в одной сущности, сохраняются при возврате к ней.
4. В превью нет неразвёрнутых плейсхолдеров вида `{{...}}`.
5. Копирование кладёт в буфер собранный промпт целиком, включая завершающие блоки.
6. «Сделать задание по этому уроку» переключает сущность с сохранением темы и класса.
7. Скачивание отдаёт `.md` с читаемым именем файла.
8. `?embed=1` скрывает шапку и футер.
9. Страница работает на ширине 375 px: ничего не обрезано, превью доступно.
10. `npm run lint:all` и `npm run build` проходят без ошибок и предупреждений.
